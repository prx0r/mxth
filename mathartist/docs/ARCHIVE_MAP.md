## What this build changed vs raw v3.3.0

1. Release hygiene (per `REVIEW.md` §Recommended next step): `package.json` 3.1.0→3.3.0, README H1 V3.1→V3.3, all `__pycache__`/`.pytest_cache`/`*-shm`/`*-wal` removed, pytest already declared in `requirements-dev.txt`.
2. **NS26 upgraded** from legacy `interpretation_genes` to evidence-backed `control_surface` (every control has provenance/role/claim_scope) + frozen trajectory dataset (`app/static/data/ns26/`) generated by `tools/generate_trajectories.py`, rendered by a trajectory-driven `ns26.js` + frozen `ns26_core.js`. DERIVED label kept prominent.
3. Missing structures built: `corpus/tsubuyaki/local_registry.jsonl` (attributed fetch or honest fixture), `docs/benchmarks/v3.3-corpus/` (real NS26 audit artifacts), `app/static/data/imported/` example, seeded demo DB.
4. Dashboard defaults to NS26; DERIVED provenance banner added; all renderers smoke-tested.

## Build findings (honest anomalies, not silently fixed)
- Regenerating trajectories with the bundled generator reproduces LENIA and two bioelectric variants byte-exactly, but NOT the shipped `french-flag.f32.bin`. The shipped bytes were kept as the frozen source (bundle hash unchanged); the generator discrepancy is recorded in `CHANGELOG_V3.3.md`.
- The `tsubuyaki.art` full archive (`data/sketches.json`, 994 sketches) is metadata + code pointers, not inline code; code was fetched file-by-file into the local-only cache with per-file SHA-256.
- NS26's first renders were diffuse speckle; photogenic defaults (threshold 0.3, zoom 1.2) were set from rendered evidence, changing only observation defaults, never source math.
